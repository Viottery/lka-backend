LKA Windows x64 便携包（2026-10-04）

使用方法
1. 把整个压缩包复制到另一台 Windows 10/11 x64 电脑。
2. 完整解压到你有写权限的本地目录，例如 D:\LKA。请勿在压缩软件内直接运行。
3. 双击 Start-LKA.cmd。首次启动会按解压路径定位自带运行环境；无需安装 Python、
   Java、Gradle、WSL 或 Docker，无需下载 Python 依赖。建议使用较短的解压路径。
4. 桌宠启动后打开任务窗口；也可在浏览器访问：
   http://127.0.0.1:8780/desktop-pet/chat.html?backend=http%3A%2F%2F127.0.0.1%3A8765
5. 退出时双击 Stop-LKA.cmd。搬动目录前先停止程序，搬动后重新用 Start-LKA.cmd 启动。

只使用网页：Start-LKA.cmd -NoPet
更换端口：Start-LKA.cmd -BackendPort 8875 -FrontendPort 8890
对应停止：Stop-LKA.cmd -BackendPort 8875 -FrontendPort 8890
已被其他程序占用的端口不会强行释放；请使用其他端口。

已经保留
- 前后端代码、桌宠角色/资源和当前已配置的应用参数。
- 模型提供商、模型选择与必要 API 密钥；前端检索/QQ 接入配置与密钥。
- 原有有效 Outlook/IMAP 配置和已存在的 Outlook 授权凭据。
- 全局界面默认值、后台/记忆功能开关、全局指令、桌宠偏好。
- 原生 Python 3.12、相互隔离的 Python 运行依赖、Java 21 和已编译桌宠。
- 仅与当前应用有关的浏览器界面偏好；不复制会话或浏览器整个配置目录。

不会带入
会话、消息、记忆内容、邮件正文/附件、项目/工作区文件、业务数据库、日志、
测试/评测、历史浏览器会话、QQ 客户端记录。新的业务数据库和工作区保存在本解压目录下。
原电脑的绝对工作区路径改为本包 workspaces；其他 API 和邮件配置保留。
如果邮件自动同步原本启用，首次正常启动会按原配置重新拉取邮件。

配置位置
backend\.env                    后端密钥与环境配置
backend\config\local.toml        模型、邮件、后台和检索设置
backend\config\secrets\          已存在的邮箱授权凭据
frontend\.env                   前端/QQ/检索接入配置
frontend\data\pet\               桌宠角色配置与偏好
settings\                       导出的全局偏好、依赖清单及可用的外部 QQ 配置
frontend\logs\                  启动日志

使用边界
- 调用远程模型、邮件和网络检索需要联网，API 费用与账号限制仍按原服务执行。
- 邮箱服务可能要求新电脑重新授权；已保留登录所需的配置，不能保证旧 token 永久有效。
- QQ 接入需要目标电脑另行运行对应 QQ/OneBot 桥接服务并登录。本包保留接入参数及
  找到的桥接配置，不搬运 QQ 客户端、登录会话或历史聊天。
- 已附带当前配置使用的本地语义检索/重排模型，位于 models；无需在新电脑重新下载。
- 外部 Codex 工具仍需在目标电脑独立安装和认证。
- Java 桌宠需要电脑图形驱动支持；若桌宠无法显示，可使用 -NoPet 的网页方式。

校验与保密
首次启动前可运行 Verify-Package.cmd，检查所有文件的 SHA256。
程序启动后配置、邮箱 token 和 pyvenv.cfg 可能改变，再次校验出现对应变化是正常的。
压缩包中包含你的 API 密钥和邮箱授权信息，应作为私人备份保存，不要公开上传或转发。
