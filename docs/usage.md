# 日常使用

## 会话与项目

每个会话使用明确的 `session_id`，可以独立开展任务和继续追问。
项目关联一个工作区和稳定的项目身份，同一项目可拥有多个会话，并使用项目记忆。
修改项目显示名称不会移动目录；登记项目也不会创建文件夹。

开始文件或代码任务前，确认当前会话的工作区是目标目录。
相对文件路径和命令工作目录通常从该工作区解析；Windows 执行 PowerShell，
Linux 执行 bash，系统不会自动翻译两种 Shell 的命令。

## 邮件与事项

可以先问“这周有哪些邮件需要我处理”，再按发件人、时间或具体事项缩小范围。
邮件清单、正文阅读和事项整理是不同操作；看过元数据不代表已分析全部正文。
大量邮件可使用启用后的邮件专家做快照、批量加载和分片整理。

事项独立保存，可带邮件、消息或文件等来源。邮件内容通过正常对话和工具读取，
不需要单独的邮件 Agent 入口。创建或更新事项前检查重复，并按安全设置处理确认。
消息来源的事项候选有专用人工批准流程，不能用普通工具审查替代。

## 消息与人物档案

先接入采集器并允许记录指定会话。记录完成后，可查找原始消息、相邻上下文和会话显示名；
启用模型分析后再形成话题、重要候选与人物档案。
昵称可能重复，人物身份按会话与真实 sender ID 区分。

注意查看来源时间、已处理范围和是否有更多记录。
消息分析会受调度与配额影响；采集停止、网络断连或分析等待时，不应把空结果解释为没有新消息。
人物摘记可以纠正或隐藏；它们是来源有限的观察，不自动成为个人长期记忆。

## 知识与网页

把资料导入知识库，或让助手按工作区路径读取文件。回答后可以继续问原文、具体段落和出处。
长工具结果先展示重点，原始内容保留本地，需要时使用工具继续读取。

网页搜索先得到候选及摘录，正文通过公开网页读取工具取得。
已有网页快照可以继续定位和分页，想确认最新情况时明确刷新；抓取时间不是正文发表时间。
登录页面或依赖 JavaScript 的页面可在浏览器中查看。

## 长期记忆

全局记忆用于跨项目偏好，项目记忆用于某个工作区的约定。
开启学习后，后台整理近期对话、已有摘要和相关记忆，保存有长期价值的内容。
临时任务、条件、否定与撤回需要保留原意；有歧义的内容可能仍是候选。

可以查看、纠正或撤回记忆。派生 `MEMORY.md` 是记忆的本地视图，
与用户维护的指导文件分开；后台学习不改写 `AGENTS.md`。
后台整理未必赶得上当前回答，跨轮使用时应确认保存状态。

## 用户指导文件

运行时读取以下文件，实际全局位置以配置的 `data_dir` 为准：

| 文件 | 作用 |
| --- | --- |
| `<data_dir>/instructions/AGENTS.md` | 全局运行指导 |
| `<workspace>/AGENTS.md` | 项目指导，从允许的根目录到当前工作区逐层加载 |
| `<data_dir>/instructions/watches/AGENTS.md` | 定时关注的共用指导 |

文件可以自由排版，不要求固定标题。系统检测修改，更新索引与摘要；长文件可以搜索、分页读取，
不会只因超过预览长度就跳过。摘要用于导航，不代表全部规则已经进入本次模型输入。

可以手动编辑，也可以明确要求助手修改指导文件。一般偏好表达交给记忆系统，
不会自动写入指导文件；文件中的文字也不能开启未授权的工具或账号。

## 持续关注与会话简报

定义关注目标、时区、每日检查时间、允许的数据源和什么变化值得提醒。
每次检查投递简报时创建新会话，之后可以在该会话继续追问。
简报区分变化、未变、无法确认和需要决定的事项；支持暂停、恢复及立即检查。

定时检查需要后端保持运行。长时间离线后默认只补最近一次到期任务，
不连续补发全部历史检查。桌面通知和其他推送方式由前端配套。

## 查看进度与处理问题

流式对话同时提供过程事件和最终回答，客户端应区分两者。
后台作业可以查看排队、等待、失败与已处理范围；暂停分析不会自动停止消息记录。
失败时先检查模型服务、授权和配额，保留已取得的资料再继续。

读写操作经过工具校验和安全审查。文件和命令仍在当前系统用户权限下执行，
使用写入能力前确认工作区与审查方式；重要结论可以沿来源核对。
接口字段及客户端交互见 [API 说明](api_contract.md)。
