# 日常使用

## 会话与项目

每个会话使用明确的 `session_id`，可以独立开展任务和继续追问。
项目关联一个工作区和稳定的项目身份，同一项目可拥有多个会话，并使用项目记忆。
修改项目显示名称不会移动目录；登记项目也不会创建文件夹。

开始文件或代码任务前，确认当前会话的工作区是目标目录。
相对文件路径和命令工作目录通常从该工作区解析；Windows 执行 PowerShell，
Linux 执行 bash，系统不会自动翻译两种 Shell 的命令。

复杂计算、批量处理和数据分析可先查询 `bash.python_environment`，使用
`filesystem.create_file` 保存 `.py` 脚本，再以 `bash.run` 的
`python_environment="default"` 执行。Linux 命令例如 `"$LKA_PYTHON" analyze.py`，
Windows 使用 `& $env:LKA_PYTHON analyze.py`。检查退出码、错误和生成文件，必要时
读取脚本并用 `filesystem.edit_file` 修正后重跑。新文件创建不覆盖已有文件；
脚本和产物放在当前工作区的明确位置，不会自动 Git 提交。

## 打断、继续与替换任务

启用 `[management].enabled` 后，后端还提供 `kind=manager` 的特殊会话。
`POST /managers/default` 幂等获取或创建主控会话，`POST /managers` 可另建一个。
它们保留普通会话的历史、重命名和回收站行为；配置接口可保存模型默认值和管理状态。
当前后端试用支持管理工具包：分页发现和读取普通会话、创建独立任务、观察运行，
以及暂停／继续／取消和发送新指令。需先将 controller 设为 active 才能发出管理写命令；
paused 仍可对话和读取结果。Matter 助手入口可获取默认管理会话，显式启用后才可写入。
顶层管理会话可通过专用 history 工具包搜索、回读未删除的普通及管理会话；这些只读权限不下放给事务线子 agent。
主管负责规划、下发、监管和验收；复杂检索、分析与批量操作默认交给执行会话。简单搜索、明确的一次操作、进度读取和已有结果汇总可直接完成，不按工具数量机械拆分。
用户已提供完整内容的单条事项可使用 matter 包内主管轻量写入口；从源资料调查并批量整理事项应下发。主管也可直接使用已授权的只读工具，工具丰富不改变其分工。
任务返回后可用 management.read_task_result 分页读取实际回答与工具证据，再说明完成内容和验证方式；执行记录不等于来源当前未变。

可以直接交代多条工作，不必先创建项目。即时问答无需建立 Matter；需要跨轮管理的抽象责任可记为 internal，
具体用户行动记为 user。内部事项允许没有截止时间，不进入用户列表、日历和规划进度。
主管可读取 Matter；创建、更新和关联使用有版本校验的 organize_work，绑定长期目标后以 Matter 为业务事实。
把内部结果转为用户待办时更新原事项的 visibility 和日期，不重复创建。

通过 `/managers/{session_id}/goals` 或 `management.set_goal` 保存目标，可设置带时区的
`next_wake_at`，或用 `wait_run_id` 等待普通任务终态。定时器触发一次后清除，需明确设置下一次。
另启用 `autonomous_enabled` 后，目标到期或关联任务结束会在会话空闲时唤醒后台管理轮，
无需保持浏览器打开。暂停 controller 仍保留新事件，恢复 active 后再处理。
自主轮的目标修改先作为提案，随最终回答一起提交；失败或版本变更不会留下半份新计划。
`/events`、`/executions`、`/deliveries` 可查看事件、运行绑定和已发布本地消息引用。
这是本地交付记录；外部主动通知尚未实现。用户输入仍使用原会话冲突、暂停和替换流程，
尚无自动抢占或持久输入排队。后台等待审批／答复时会以去重事件提醒主管，并提供原工作线的问题／控制指引，仍使用原用户入口；主管不会代用户批准。

可以在前台管理会话中明确委托“提醒近期事项”或“每周五 18 点汇总”，分别配置近期提醒策略或周期目标检查。
近期提醒关注逾期、近日期限和今天安排，按事实去重；周期支持一次性、每日、每周及有效期。
关闭页面仍可执行，前提是后端运行且自主管理开关与 controller 均已启用。
暂停一条工作、暂停主管和暂停未来策略分别控制，不自动取消其他独立任务。
已有 watch 可由主管发现并订阅：每份新简报或仅有变化时提醒。订阅只绑定明确 watch 的当前授权范围，
变更来源范围后需重新确认订阅。主管不会因此自动创建新 watch 或取得其他来源权限。
可以在前台委托静音或“稍后再提醒”：捕获继续，通知留待解除后重验；默认仍保留关键决定提醒，
设置 allow_decisions=false 可一并静音。

多线结果可以关联到 Matter：使用 start_work 原子检查依赖并创建绑定任务；既有任务可 assign_existing。
读取真实结果后 review；accepted 仅给出有版本的完成更新建议，仍需 organize_work 应用。
自主轮先发布核验，后续轮再完成事项。需要等待依赖或写资源时使用 queue_work，Matter 可选，不必为了排队建立待办。
受理后已有稳定的 run，后台按依赖、优先级／等待时长／软期限和跨主管轮转释放。
默认只读任务实际不开放写工具；写任务需明确工作区，队列内同工作区（含子目录）保持互斥预留。
等待用户／暂停不占工作线程，但保留写预留直到原运行终结。改变排队任务指令需取消后重新排队。
普通直接任务不纳入这些预留；它们和手动恢复仍由原控制入口及共享模型资源约束。

多个事务可由主管用 delegate_work 分配给独立事务线子 agent。它们可以自己处理，或创建和监管多个执行会话，
在任务完成后先审阅结果，再用 report_delegate 回报；主管原轮结束后会由回报触发新轮并产生消息。
这些显式委托不需要开启普通自主管理。list_delegates/read_delegate 可检查归属、运行与报告；
需要关键决定时报告 needs_decision，由主管转交用户。子会话空闲后可用 instruct_delegate 补充指令并继续原事务线。
control_delegate 的 pause/cancel 会收回执行权限并取消未完成运行；pause 后待运行终结可补充指令继续，cancel 后不复活。
完成报告必须等自身任务终结；任务执行结束并不等于事项已经业务完成。

任务创建后写入持久派发队列，API 进程按持久租约独立执行原 run；浏览器关闭或管理轮结束不取消任务。
指令包含发送方、整理目的、服务端引用的用户原话和相关运行，作为工具来源保存，
不触发用户偏好提取。普通执行任务不开放管理工具；事务线子 agent 仅开放自身任务的管理工具，并冻结工具与路径范围。主管自身不绑定默认工作区。前端可在 controller.default_execution_workspace 配置默认执行父目录，新任务在其中建立独立工作区；未配置的纯数据任务无工作区且不能使用工作区工具，不回退到后端开发目录。修改默认值不改变已受理任务。
运行中任务必须先请求暂停并等待 `run_paused`，才能用 `expected_run_id` 发送替换指令。
每条管理命令使用稳定 `command_id`；重试返回原回执，改参数复用 ID 会冲突。
等待确认或用户答复时，仍从原确认／答复入口操作，普通 resume 不代替批准或回答。
智能体创建会话不免除高风险审批；主管与子 agent 只能提示用户处理原审批请求，不能代批或通过换会话／替换指令延用批准。

`GET /sessions/{session_id}/runs` 可从另一端发现当前及历史主运行，然后复用运行查询／SSE。
同一会话在 queued、running、paused 或等待状态时保留一个主运行位置；直接创建竞争运行返回 409，
需先结束、继续或替换原任务。默认全局助手可通过消息队列连续发送多条，当前轮结束后按顺序自动处理。
已发送消息会持久保存，关闭或刷新页面不丢失；排队中不代表当前运行已经读取这条消息。
暂停／等待审批时后续消息继续排队；失败或取消暂停队列，可显式继续处理剩余消息，原失败消息不自动重试。不同会话可独立运行。后台派发遇到无检查点的中断运行会失败待检查，
不会重新创建任务重做未知副作用。任务结果可按需读取；启用自主管理后也可由持久事件唤醒。外部主动通知尚未实现。

管理会话不参加空白自动清理。删除前需设为 paused，结束该会话尚未终结的运行，
并暂停或转交活跃目标；恢复后仍保持 paused。已删除的主控入口不会自动重建，
可恢复原会话，或用 `POST /managers` 的 `make_default=true` 显式另建并切换。

后端支持把进行中的 LangGraph 根任务暂停在检查点，再继续原任务，或用新消息替换。
客户端创建任务时传 `resumable=true` 即可按本次任务启用；无需修改 legacy 默认配置或
模型推理策略。已开始的 legacy 任务不能追补检查点。
打断请求返回不等于已经停下：需等待 `run_paused`，当前模型调用或工具步骤可能仍在结束。
继续沿用原 run；替换创建同一会话中的新 run，旧任务不再继续。原消息与操作记录保留，
已经完成的写操作不会撤销，恢复不会重新执行已保存的工具步骤。

打断会停止整个 DAG 的新任务派发，通用子 Agent 一起保存检查点并暂停；只有整棵树
停稳后根任务才显示 `paused`。继续复用原节点及结果；替换取消旧树的调度资格，历史
DAG 和 trace 不删除。新任务的模型会看到已执行操作的交接摘要，可继续读取完整缓存，
便于核查修改或按用户要求回退，不会自动撤销文件或外部操作。
没有恢复能力的 workflow／外部专家需先结束已开始的执行，再确认根任务暂停；
尚未开始的任务可以暂停。暂停不是强杀进程，无法停止的外部执行仍可使用永久取消。
暂停不替代安全审批或待回答问题，`cancel` 仍是永久终止。客户端对接与状态事件见
[可恢复打断与新消息替换](api_contract.md#可恢复打断与新消息替换)。

## 邮件与事项

可以先问“这周有哪些邮件需要我处理”，再按发件人、时间或具体事项缩小范围。
邮件清单、正文阅读和事项整理是不同操作；看过元数据不代表已分析全部正文。
大量邮件可使用启用后的邮件专家做快照、批量加载和分片整理。

事项独立保存，可带邮件、消息或文件等来源。邮件内容通过正常对话和工具读取，
不需要单独的邮件 Agent 入口。创建或更新事项前检查重复，并按安全设置处理确认。
消息来源的事项候选有专用人工批准流程，不能用普通工具审查替代。

工作台“待办与规划”按收集箱、今天、接下来、日历、项目规划和完成记录组织行动。
桌宠快速窗口中的待办打开独立原生窗口，关闭后保留界面状态，再次打开聚焦已有窗口。
计划哪天做、精确开始/结束时间与截止日期分别保存；日历支持周、月、日程视图，拖动只改变时间安排。
项目规划可以独立存在，也可关联目录，支持目标说明、阶段、行动顺序和全部行动进度。
快速输入支持“明天 15:00 整理资料 45分钟”等简单日期表达，保存前显示解析结果。
对话管理使用独立会话，经现有 Agent 和 matter 工具创建、拆分或修改，不覆盖原对话草稿。
页面优先显示本地缓存，60 秒内重新打开不重复请求；过期后增量同步，失败仍保留已有内容。
并发冲突保留草稿，可载入最新版本合并核对。消息来源事项仍通过消息中心的专用审批流程处理。

## 消息与人物档案

先接入采集器并允许记录指定会话。记录完成后，可查找原始消息、相邻上下文和会话显示名；
启用模型分析后再形成话题、重要候选与人物档案。
昵称可能重复，人物身份按会话与真实 sender ID 区分。

注意查看来源时间、已处理范围和是否有更多记录。
消息分析会受调度与配额影响；采集停止、网络断连或分析等待时，不应把空结果解释为没有新消息。
人物摘记可以纠正或隐藏；它们是来源有限的观察，不自动成为个人长期记忆。

## 知识与网页

把资料导入知识库，或让助手按工作区路径读取文件。回答后可以继续问原文、具体段落和出处。
长工具结果先展示重点，原始内容保留本地，需要时使用工具继续读取。

也可以把文档作为会话附件输入，复用图片的上传接口和 `attachment_ids`。
图片交给视觉模型，文档通过本地解析器提取文字；纯文档可使用文字模型，允许混合输入。
长文档先提供有来源标识的预览，再通过 `attachments` 工具继续读取或搜索，不自动入库。
上传 PDF 同样依赖文字层，不自动 OCR；解析警告会说明可能遗漏的页面或格式。
接口与文件限制见 [会话文件附件](api_contract.md#会话文件附件)。

PDF 使用 `documents` 工具包：先 `open` 获取页数、目录和文件哈希，后续
`read_pages`、`find`、`render_page` 都携带 `expected_sha256`，防止混用修改前后的文件。
默认按需提取文字；`layout` 模式保留近似间距。阅读返回页码和字符位置，长页按照
`next` 继续，不跳过截断内容。搜索只覆盖文字层，未提取到文字不代表该页没有信息。

扫描页、图表和复杂布局可用 `render_page` 输出 PNG，再经审查使用
`vision.inspect_image` 提问。原始 PDF 保持不变；文字提取和视觉模型解释都不承诺完整
还原页面。渲染需要明确的输出路径且不覆盖文件，图片发送遵守当前模型配置和工具审查。
用户要求合计等计算时，视觉分析会区分图中原值与根据可读数值计算的结果；结果未印在
图片上不应成为省略计算的理由。输入缺失或不清晰时说明限制，单纯转录仍只报告可见内容。
加密文件须先提供解密副本。PDF 工具直接读取文件，不会因阅读而自动创建索引；显式工作区
索引可以另外提取 PDF 的文字层加入知识库。

文件类型优先处理方法由 `app/domains/file_processing.py` 的策略表维护，客户端可通过
`GET /knowledge/file-types` 查看同一列表：Markdown/TXT 使用原生 UTF-8 读取，PDF 使用
原生解析；DOCX、PPTX、XLSX/XLS、HTML、EPUB、CSV、JSON、XML 和 Outlook MSG 使用
MarkItDown 本地转换。调用 `POST /workspaces/index` 并设置
`options.index_knowledge=true` 才会入库，普通工作区扫描仍只记录文件数量。

索引中的警告说明转换可能遗漏图片文字、布局、公式或附件。Excel 转换侧重缓存数值，
不能替代 Python 对公式和工作簿的分析。扫描 PDF 没有文字层时明确报告提取失败；本轮
不会自动调用视觉模型。图片、音视频、ZIP、旧 DOC/PPT 和未知类型不自动加入索引。
转换失败或受限时保留已有证据，查看 `knowledge_errors` 后再处理文件并显式重建。

网页搜索先得到候选及摘录，正文通过公开网页读取工具取得。
已有网页快照可以继续定位和分页，想确认最新情况时明确刷新；抓取时间不是正文发表时间。
登录页面或依赖 JavaScript 的页面可在浏览器中查看。

## 长期记忆

全局记忆用于跨项目偏好，项目记忆用于某个工作区的约定。
开启学习后，后台整理近期对话、已有摘要和相关记忆，保存有长期价值的内容。
临时任务、条件、否定与撤回需要保留原意；有歧义的内容可能仍是候选。

可以查看、纠正或撤回记忆。派生 `MEMORY.md` 是记忆的本地视图，
与用户维护的指导文件分开；后台学习不改写 `AGENTS.md`。
后台整理未必赶得上当前回答，跨轮使用时应确认保存状态。

记忆中心的纠正和停止使用支持可选原因，例如事实错误、表达不合适、已过时、重复、
不值得记住或不想保存。系统从启用后记录这些明确用户操作，作为后续优化记忆判断的样本；
未选原因时只记录操作，不推断舍弃动机。手动导入 `MEMORY.md` 纠正和会话中的明确撤回
也会记录，自动维护操作不充当用户反馈。
记忆整理可参考少量相关的非敏感偏好纠正，最多3条、合计2000个JSON字符，仍需本轮用户
来源支持；目前没有自动训练模型。选择“不想保存”会清除相关纠正链的反馈文本，
只保留操作与原因等元数据。停止使用仍是软撤回，原有记忆历史与来源审计不因此物理删除。

新偏好会先匹配相关旧记忆：同义表达补充来源，明确变化更新版本。
后台另按全局／项目整理重复和互补片段，保留场景、否定、例外、来源与有效期限；
不同使用场景和不确定关系不强行合并。过期或来源失效的条目不参与合并与召回。
旧条目及版本历史保留，合并后同步派生 `MEMORY.md`；人工改过的文件不被覆盖。
管理接口可查看整理状态、请求一次整理、查看合并历史并撤销未被后续修改的合并。
撤销后的同一组合不会自动重新合并；后续明确纠正仍可建立新的记忆版本。

| `<data_dir>/instructions/AGENTS.md` | 全局运行指导 |
| `<workspace>/AGENTS.md` | 项目指导，从允许的根目录到当前工作区逐层加载 |
| `<data_dir>/instructions/watches/AGENTS.md` | 定时关注的共用指导 |

文件可以自由排版，不要求固定标题。系统检测修改，更新索引与摘要；长文件可以搜索、分页读取，
不会只因超过预览长度就跳过。摘要用于导航，不代表全部规则已经进入本次模型输入。

可以手动编辑，也可以明确要求助手修改指导文件。一般偏好表达交给记忆系统，
不会自动写入指导文件；文件中的文字也不能开启未授权的工具或账号。

## 持续关注与会话简报

定义关注目标、时区、每日检查时间、允许的数据源和什么变化值得提醒。
每次检查投递简报时创建新会话，之后可以在该会话继续追问。
简报区分变化、未变、无法确认和需要决定的事项；支持暂停、恢复及立即检查。

定时检查需要后端保持运行。长时间离线后默认只补最近一次到期任务，
不连续补发全部历史检查。桌面通知和其他推送方式由前端配套。

## 查看进度与处理问题

流式对话同时提供过程事件和最终回答，客户端应区分两者。
后台作业可以查看排队、等待、失败与已处理范围；暂停分析不会自动停止消息记录。
失败时先检查模型服务、授权和配额，保留已取得的资料再继续。

读写操作经过工具校验和安全审查。文件和命令仍在当前系统用户权限下执行，
每次工具调用（包括只读调用）都会按安全设置审查。工作区外的文件路径或 Bash `cwd` 会申请
针对该精确路径的本次批准；路径在执行前重新解析，符号链接目标变化后需要重新审查。
Bash 对工作目录的批准不限制命令参数可访问的文件。使用写入能力前确认工作区与审查方式；
重要结论可以沿来源核对。
接口字段及客户端交互见 [API 说明](api_contract.md)。
