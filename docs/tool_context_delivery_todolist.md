# 工具上下文交付优化 TODO（2026-10-06）

## 目标与约束

首屏仍快速、简短；明确续读时交付较大的完整片段。模型应知道原始资源、
搜索候选、操作回执的区别，优先沿合法本地读取入口填补缺口，而非重新联网。
不靠角色、站点、任务关键词硬编码，不改变工具授权、单步一个动作、安全门、
会话隔离和完整模型请求容量检查。保留全部原始工具结果及本地审计。

执行顺序：缓存/交付合同与定向测试 → 独立网页获取修复 → 集成、回归与报告。
采用一个低成本子 Agent 处理独立网页集成，其余由主 Agent 实施；不做付费全量评测。
本 TODO 的验收是工程合同和案例回放，不等于证明任意模型都会正确选择工具。

## 验证记录

### 已实现合同

1. `ToolSpec.output_selected_content` / 注册 `selects_context_page` 回调标记主动选页，
   不从工具正文读取能力配置。适配单结果28k tokens／64k字符时完整交付；超限仍走
   ≤7k字符预览，原始artifact与真实可见区间保留。决策观察工作集32k tokens／128k字符，
   根答案64k tokens／256k字符；完整请求与Child预算仍是最终上限。标记/续读索引也占上下文，
   这些工作集数值不是模型支持容量或供应商计费token承诺。
2. `observation.read` 文本默认8000、上限16000 Unicode字符；旧显式小页不变。
   默认页的长中文、英文均验证不再次折叠；在无本地tokenizer、采用保守UTF-8字节计数时，
   16000中文字符仍可能超过单结果预算，必须按可见区间续读或减小源页，不能盲目跳到next_offset。
3. `_resource` 指向原始网页/搜索资源；`_result_cache` 只指单次调用回执。资源合同包含
   身份、版本、read_package、read_tool、read_input及可选find入口。观察省略和整请求裁剪
   分别保留 `omitted_resources` / `_prompt_budget.observation_resources`，最多4条；artifact
   入口最多20条。入口只是提示，ToolExecutor与当前权限、run/session、TTL仍须再次检查。
4. JSON与原生function-call决策提示均载入同一通用读取协议：优先原资源本地查询/续读，
   再读当前run原始回执；不重新联网找已有正文、不从回执查询词制造证据、不跨未交付区间翻页。
   网页规则/续读工具名只在web包及其后端合同中维护，不新增角色/站点/任务核心特殊判断。
5. 历史选取先过滤权限和存活，再对最近48个合格候选按资源去重、按任务词重排取8项。
   这是无LLM、无额外外部请求的有界选择，不是全历史语义检索，也不把旧快照变成最新事实。
6. 默认缓存搜索只扫注册正文/候选字段；显式 `scope=raw` 保留诊断能力；未知工具语义不猜。
   已声明范围外的path返回 `path_excluded_by_content_scope=true`、`complete=false`，
   不伪装成完整扫描后的零命中。缺失的合法正文列表仍可正确返回完整零命中。
7. 标题上下文绑定提取偏移，优先向后正文且不跨已知下节标题；保留普通正文的邻近条件。
   稀疏HTML（可见文本<1200字符）可以尝试隐藏的有标题结构记录；只有实际隐藏正文且比
   可见提取更丰富时采用，明确标记备用方法。排除嵌套script/style/form等，不执行任何脚本。
   `text/x-wiki` 按原文读取，非白名单MIME错误携带有界实际类型。

### 工程前后对照（合成回放，不是生产速度/准确率提升承诺）

| 场景 | 原问题 | 新的可验证结果 |
| --- | --- | --- |
| 主动长文本续读 | 页内正文又按4k/规则预览折叠 | 默认8k中文/英文完整进入观察；16k英文仍完整，超大中文保留部分标记/缓存入口 |

### 仍存在的限制与后续实测

- 工程验证证明模型请求中确实有协议/合法入口，脚本决策能从缓存找到初屏之外的事实；
  不能证明任意真实LLM都愿意或能正确利用。没有重放223秒真实会话，因此没有新端到端
  时延、真实token账单或答案准确率；后续可用新会话做一次定向验收，无需全量付费评测。
- 网页query仍是有界词法匹配：短词可能命中长词内部、CJK不是语义分词；review发现的
  子串误召回为既有问题，暂记录，不在本轮叠加领域或任务关键词规则。
- 备用提取只覆盖可识别的HTML内结构记录；canvas、脚本运行后才产生的数据、登录墙、
  复杂渲染仍需其他工具，缓存不能恢复从未采集到的正文。隐藏记录也不认证真实性。
- 相关性按最新同资源观察去重，不合并其所有历史正文；跨run通用回执仍不可读，网页
  跨turn依赖原快照留存。非常久远或被淘汰的数据不保证自动召回。
- 尚未同步/重启用户的Windows原生后端，旧快照保持旧提取版本；需要refresh建立新快照
  才能获得备用提取正文，不能把旧968字符快照误称自动修复。
