## 实现和边界

`app/core/memory_learning.py` 是共享的上下文整理器。后台依然只由已完成回答触发，
任务存 ID 而不是正文。默认读取最近 12 条 user/agent 消息，正文合计 12000 字符，
单条预览最多 4000 字符；摘要最多 2000 字符，旧记忆最多 12 条、每条 800 字符。
这是额外的背景输入预算，不改变前台对话窗口；源消息和 trace 仍保留原文。
后台快照终点是触发用户消息，不能偷看排队期间的新轮次。摘要若已包含未来消息则不提供；
可识别的项目切换处截断历史并去掉摘要，项目记忆不能写入不存在的项目。

本地可识别的偏好不调用额外模型。未命中且有潜在长期价值的消息走配置模型，普通问候和
一次性任务优先跳过。模型组织独立、规范化的 claim，保留条件、否定、范围和有效期，
并返回来源 ID/原文片段。无需 claim 是原句或使用“记住：”固定形式，但不能捏造消息 ID。
只提取本轮新增、改变或确认的内容，不把全部历史重新学习一遍。

直接/已确认、durable=true、confidence>=0.85 的新合同结果可以立即发布；弱推断候选
不因引用了多条历史而视作多次用户确认。旧格式抽取结果仍走旧校验，便于兼容既有评测。
有用内容可自然学习，不要求用户逐条授权；记忆仍不能扩展工具、路径或外部操作权限。

模型以相关旧记忆 ID 指明 equivalent 或 replace，确定性服务执行：前者保留 ID 并链接
来源，后者创建新 ID 和 supersedes_id，旧条目不再注入。并发版本改变时后台重试；
已撤回/失权目标不静默恢复。过期记忆按现有服务过滤，稳定偏好不机械设置 TTL。
语义重复判断来自模型，不声称实现了全库完美语义去重。

普通对话的模型整理在后台，不增加前台模型调用；`memory.remember` 的明确即时保存允许
同步等待一次有界整理，以便返回真实落库回执。工具原有 evidence 参数仍可用，新 content
参数可描述目标偏好。返回首条 memory、全部 memories、文件同步状态，拒绝时不声称保存。
LLM 使用既有配置与资源控制，不增加硬编码模型或访问邮件/工作区的后台能力。

新增配置通过既有后台配置 API/schema 暴露：`allow_remote_extraction=true`、
`extraction_context_messages=12`、`extraction_context_chars=12000`、
`auto_publish_min_confidence=0.85`。旧配置显式关闭不会被默认值自动覆盖；重启生效。

## Bad case 与解决方法

| 场景 | 原因 | 处理与效果 |
| --- | --- | --- |
| 上轮完整偏好，本轮“把这个要求保存到全局记忆”两次拒绝 | 工具/后台只看当前句，精确规则无法解析指代 | 有界近期对话 + 多用户来源，离线真实原话回归保存完整偏好并跨会话加载；真实模型保存角色风格及保持工作能力的约束 |
| “后续一直”没有被识别，后台任务成功但无条目 | 固定词法规则与关闭的模型兜底 | 默认模型整理，正常长期事实也可直接生效 |
| 保存成 active 但新会话没有加载 | 新路径遗漏 sensitivity，落成默认 personal | 明确 normal；新增实际上下文提供器验证，非只检查数据库 |
| 更正后不能再合并来源 | correct 生成新 ID，不符合内容哈希 ID 假设 | add_source 按精确 ID 加锁、CAS、链接来源；更正与同义合并测试通过 |
| MEMORY.md 手改后工具报整体失败 | 文件冲突异常类型未被单独捕获 | 保留数据库结果与手工内容，返回 conflict_or_unavailable |
| 用户撤回时后台提取正在运行 | 撤回被当成任务故障 | 发布抑制作为终止跳过，租约与版本竞争仍走原有队列机制 |

## 保留限制

- 语义归纳、指代、条件保留仍可能受模型影响；明确歧义返回未保存，不能假装已记住。
- 字符预算是模型输入前的粗界限，最终模型请求仍受既有 token/context 预算约束。
- 超出近期窗口的指代不自动全库扫描；大于 20000 字符的用户消息不进入本轮后台模型学习。
- 相关旧记忆是有界集合；同义合并/更新不是全库一致性的语义证明。
- 不自动迁移过去误写的指导文件或补跑整个历史，避免未经核对改动用户内容。
- 当前 worker 保留分组/checkpoint，但上下文整理按待处理 turn 调用，不再使用旧单句批量分区
  适配器；需要后续真实流量评估 burst 成本，不能声称本轮减少了所有后台 token。
