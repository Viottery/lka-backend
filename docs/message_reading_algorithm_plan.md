# 消息阅读算法与人物画像实施方案

设计日期：2026-10-05。状态：工程实现及历史离线验收已完成，人工语义门槛待验收、新版未部署。本文承接
[消息阅读后台服务设计](message_reading_service_design.md)，执行项见
[消息历史 TODO](message_history_todolist.md)。本文不改变生产配置或现有 API 合同。

目标是在已采集的真实消息上迭代主要话题、热点、重要信息和活跃人物画像，同时控制后台
模型成本。先比较固定数据上的质量与成本，再决定生产策略；不以摘要好看或 token 少作为唯一成功标准。

## 数据范围与授权

截至 2026-10-05 13:06 的只读统计，三个群累计 6765 条消息，其中 3318 条为 v2；
原私聊另有 8 条，不纳入本方案的远程评测。随后以该截止点制作了冻结快照，后续采集不改写它。
该批数据足够启动短期回放，已冻结为独立授权快照；不足以证明长期画像稳定或整个采集时段无缺口。

用户已同意这批三个白名单群文本用于远程 LLM 消息分析、人物画像和效果评测，并允许
群侧重点留空、由 AI 归纳。此授权不自动开启生产 analysis、不扩大白名单、不上传媒体
原文件、不开放 QQ 写操作、不创建 matter。已明确的 provider 变更确认及 source/account
权限检查继续有效。真实 badcase 的本地额外副本仍沿用预览与明确保存同意流程。

制作快照时记录实际末尾 seq、采集许可代次、记录范围与 consent 时间；使用 SQLite backup
生成一致副本，导入隔离回放库只保留三个群的必要消息与元数据。生产采集不停、不回写
生产 covered_seq、画像或结果。快照、标注、化名映射、模型结果与报告留在被 Git 忽略的
本地目录；公共文档只记录方法和汇总指标。不把整库备份作为模型输入。

快照冻结数据，不冻结永久许可。独立 evaluation grant 明确本次范围、provider、预算与
有效状态；每次实际 dispatch 和发布都检查当前 grant，并经可信管理通道核对源会话当前
记录许可及 capture_epoch。不能仅凭副本里的旧 record_enabled/analysis_epoch 放行；
无法完成当前校验时延期，不继续外发。生产 analysis=false 不否定已单独授权的回放，
也不能被试验入口改成 true；撤销试验授权或源许可后停止新请求并 fence 旧输出。

发送前对账户、群、用户及消息 ID 建立稳定的本地化名映射。正文中出现的 QQ 号、姓名等
仍可能可识别，化名不等于匿名化；先用有界规则替换明显身份信息，展示残留风险。
必要日期、否定、更正和任务实体不能为脱敏而被静默删掉。外发许可范围和实际 provider
身份写入 manifest，不把密钥、端点或聊天正文放入普通运行日志。
顺序固定为原文 → 可审计脱敏投影 → codec。codec 的逐字符一致针对脱敏后的投影，
投影另外检查与本地原文的身份／实体／时间对应；脱敏损害关键语义时标明受限，不能宣称
对原始全文无损。普通结构对照也使用同一脱敏投影，避免不公平比较。

## 处理链路与现有模块

```text
不可变原始消息与当前许可
  → 本地特征扫描、活跃人物计数、候选片段
  → 固定范围与处理 manifest
  → 可还原紧凑编码，或明确部分覆盖的选择性输入
  → 一次有界模型分析
  → 来源、作者、版本与租约校验
  → 原子发布话题、信息卡、人物候选与覆盖记录
  → 低频合并群侧重点和人物摘要
```

复用 `message_history.py` 的身份、原文与许可，`message_reading_runtime.py` 的调度与
family，`llm_workloads.py` 的预算账本，`message_reading_results.py` 的结果／证据与阅读状态。
模型调用仍由 `message_analysis.py` 和现有 LLMService 承载，不在 domains 内调用模型。
紧凑编码、选择策略、人物统计与校验放入确定性领域模块；新增领域 prompt/schema 放在
消息包内部分析模块，不增加通用 Agent core 的领域特判，不新增长期 ReAct 子 Agent。

现有 `ReadingProfile`、`reading_profile` 和 `conversation_profile` 是用户显式关注配置，
不改名、不改义、不允许模型覆盖。新对象分别使用 `ConversationFocus` 和 `ParticipantProfile`。
当前严格 v2 分析 envelope 不允许直接追加字段；画像／侧重点使用单独版本化 schema 和
analysis generation，保留旧 v2 输出读取，不拿旧摘要冒充新功能。

## 本地特征与话题候选

所有入库消息先做不调用 LLM 的信号扫描，包括原生 @、reply、显式关注词、期限、
行动请求、更正、否定、数值变化、链接及内容类型。候选是待核实信号，不保证事实真实。
本人身份由用户已确认的配置提供，不能猜测昵称；原生 @全体与 @本人保持区别。

初版话题候选结合以下信息，不默认安装 embedding 模型或向量库：

- 同会话原生 thread/reply 边，以及有界时间邻近关系；未解析回复明确为 unresolved。
- 有辨识度的关键词、实体和词组重叠，通用口头语权重低；参数由开发样本校准。
- 近期已发布话题的有限候选列表，保留结论、分歧和未解决问题，而非仅比较标题。

默认用 15 分钟基础窗口形成候选片段；回复链可延伸，但单片段初值最多 100 条、跨度
最多 60 分钟，并继续受完整 prompt 限额约束。跨窗口讨论用有界已知话题和必要先前证据
连接，不把整段链全部加载。不同话题交织时允许并行候选；边界、不确定匹配与被排除
的历史候选都记录在 manifest。模型建议归并，持久 ID、revision 和来源验证由服务端决定。

话题代表证据与完整成员关联分开：现实现的每话题 source_message_ids 上限 50，跨分片
超过上限会失败，不能直接扩大窗口后宣称已解决。新 schema 需要有界代表引用，以及分片级
成员分配与服务端分页关联，确保大话题可完整发布。只有经模型分配并校验的成员计入语义
话题参与量；本地相似聚类和未输入的折叠消息另记候选／观察量，不冒充已确认话题成员。

热度沿用群内独立参与者、去重量、新近度和讨论变化的确定性评分，单人贡献饱和。
跨群先各群排序再多样化混排。重要性另行判断，不能被热度或人物活跃度乘低；
一次性低频公告、被淘汰人物发出的重要消息仍须进入候选通道。

## 紧凑编码与选择策略

### 可还原编码作为首选版本

先减少结构冗余，不删消息内容：将重复长 JSON 键改为版本化短字段或数组，账户／群
在头部出现一次；消息和人物用批次化名；时间使用绝对基准加秒偏移，携带时区与时间质量。
对完全相同文本使用文本字典复用，但每条消息仍保留独立作者、时间、@、reply、序号和身份。

codec 必须对分析所需投影 roundtrip 一致：正文逐字符一致，作者、所有时间语义、原生
元数据与 unknown 状态不丢失。日期、更正、否定、数值和对象不能因相似折叠。
重复展示不等于删除原文；单条长消息仍分片，不采用截首尾后声明完整的方式。

固定头部明确结构解释和不可信内容边界；模型引用别名只能由服务端映射到已提供的
真实内部 ID。只有模型确实见过的文本片段才能支撑结论。tokenizer 按实际配置计数；
包含字典、schema、旧话题和映射解释的全部 prompt 一起比较，字节减少不是 token 节省证明。

### 选择性输入作为实验版本

这一路允许少送内容，但不得声称全部消息完成语义理解。采用三层选择：

1. 保护集合：本地重要信号、明确更正、行动／期限、用户固定关注人，以及这些消息必要的
   回复对象与相邻上下文。保护集合超过预算时拆片、延后或退回完整路线，不能静默截掉。
2. 代表集合：各话题候选的新信息、问题、答案、结论与分歧，均匀保留人物和时间覆盖。
   噪声仅在分析视图降低优先级；“收到”“不行”等短句有回复或否定意义时不能直接抛弃。
3. 探索集合：从剩余消息按会话、时段、发言者和罕见词分层，以固定种子抽样。
   初始探索占可选输入 token 的 10%，只是校准起点，不是遗漏概率保证。

选择不能只靠重要关键词或高频人物。为每条消息记录 retained/context_only/folded/
sampled_out/deferred、理由与引用映射；相似但有新作者／日期／数值／否定的文本不当作同一事实。
模型认定证据不足时只允许提交有界回读请求，由确定性工作流从当前授权范围补充，最多一次；
回读调用计入原 family，不开放任意工具。补充后仍不足就保留 unknown。

### 覆盖语义

保留现有完整路线 `analysis_covered_seq` 的含义，不让筛掉的消息把该水位向前推进。
新 generation 分开记录：

- `screened_seq`：本地扫描的连续范围。
- `selection_manifest`：固定范围内每条消息的决策和分片状态。
- `model_seen_spans`：实际进入请求的 message/fragment 范围及 input digest。
- `published_range`：该处理范围的结果已一致发布，不等于每条消息都被模型读取。
- `generation_published_seq`：新 generation 的连续发布水位，驱动该路线的选范围与积压计算。
- `coverage_mode=full_text|selected_text`：编码可还原且所有片段完成才可用 full_text。

任何 deferred 片段完成前均不得推进处理范围的连续发布水位。context_only 被看到不等于
作为新范围独立分析；摘要、模板或代表消息不能冒充未输入原文。UI/工具明确显示选择比例、
未输入数量、待处理量与采集缺口。选择路线发布原子性保持不变，覆盖是显式部分语义覆盖。
旧完整路线的水位保持原义；切换／关闭选择路线时，普通路线从最后真实 full_text 水位
恢复，不能跳过仅 selected_text 的区间。可能重分析的范围与成本明确预览，不能凭
generation_published_seq 给旧 covered_seq 补盖完整认证。

## 群侧重点的自动归纳

群配置使用 `focus_mode=auto|manual`，默认 auto；留空不是系统必须先询问的阻塞条件。
与用户关注配置分开保存，每群至多四个侧重点，例如技术答疑、项目协作、兴趣交流与日常社交。
这是对已观察讨论的摘要，不声称识别了群的真实正式用途。

冷启动复用首批话题分析输出候选，无足够证据时使用 general/unknown；不单独启动大模型
为整个群画像。初始进入条件是三个独立窗口重复支持某主题；支持可来自不同时段，单用户
刷屏不能构成三个独立主题证据。当前不足一天数据时明确 low_support，不把 0..1 分数
当作经过校准的概率。

默认每日最多合并一次 auto focus，采用七天衰减统计。新侧重点必须持续获得多窗口支持，
退出阈值低于进入阈值；近期临时热点只进 transient_topics，不立刻改群定位。
用户 manual 优先、可锁定或恢复 auto。模型输出只能从允许侧重点建议及解释中选择，
不能添加执行指令、改变白名单、提高预算或授权上传。

每项携带来源窗口、代表消息、confidence_label、revision、更新时间与 sample_coverage。
工作开始冻结 focus revision，不在处理中因群定位变化重写输入或重复调用；新版本仅作用于
后续工作，旧版本继续可追溯，避免每次自归纳引起所有历史任务失效。

## 活跃人物索引与有限画像

### 身份和活跃度

人物画像主键使用平台、账户、会话、sender_id。昵称／群名片只作有时效的展示信息，
不能合并同名人；缺少可靠 sender_id 的消息不生成个人档案。首版不跨群、跨账号合并，
不主动查询联系人或群成员。跨平台适配器只提供统一身份与消息字段。

对所有已观察发言者维护轻量活动索引，而非每人保存 LLM 摘要。按到达顺序处理，事件特征
使用有效发送时间，回放时钟绝不看未来消息。异常未来时间不提高活跃分；幂等重放不重复加分。

建议初值的分数定义如下，各系数需实测调整：

```text
activity = 0.45 × saturate(decayed_active_buckets)
         + 0.35 × saturate(decayed_distinct_days)
         + 0.20 × saturate(decayed_topic_participation)
decay_weight = 2 ** (-age_days / 7)
```

active_bucket 是每人每 30 分钟最多一次有效贡献；词汇复读不累计原始消息量权重。
topic_participation 基于已发布、去重的参与记录；无语义结果时该项缺失并标记，不伪造 0
来声称该人没有参与。冷启动不足多天时使用窗口参与度并降低判断置信，不处罚刚进入群的人。
语义统计升级 score_version，不与旧分数直接混排。
某一分量缺失时，仅对可用分量重归一权重，同时保留缺失标记；不把缺少话题分析当作
真实零参与。已有 topic 结果的更新基于 message/topic 唯一键，不能每重写摘要重复加分。

### 近似 LRU 的热池管理

每群初始普通热池容量 30 人，三群合计普通上限 90。这是试验起点，不是生产默认值。
排名基于上述分数，最近活动作同分 tie-break；不采用“最后一条消息立刻挤掉一个人”的纯 LRU。

- 初始候选进入条件：至少三个不同活跃桶且跨度六小时，或在两个独立话题有有效参与。
  未达到条件可以展示发言记录，但不启动稳定画像推断。
- 池满时，新人分数超过最低未固定者 25% 且两个重算点均满足才替换；默认每日重算最多四次。
- 连续 14 天不活跃且未固定进入冷态；冷态不继续发送资料给模型。回归时复用有权限的
  可验证事实，不把过期需求或旧印象直接恢复为当前状态。
- 用户可固定最多每群十人，独立于普通容量；达到全局配置硬上限拒绝继续固定并提示，不暗中淘汰固定者。

冷态只是停止更新与默认隐藏，不删除原聊天；冷态摘要可保留 30 天后清理派生摘要，
原证据按原消息保留策略不动，清理后再进入可从授权证据重建。确切保留期在实施时作为
显式设置，不在本轮操作任何真实数据库。热池外的人仍被重要信息扫描，不漏掉低频关键发言。

### 画像内容和归属

每个档案初值最多十二条有效事实、三条待核实项，显示摘要最多 240 个中文字符。
事实按 preference/characteristic/need 分类，并保存原文引用、主体、表达者、首次／最近
证据时间、explicit/observed/uncertain、状态、有效期、supersedes、来源版本与审核记录。

允许“明确偏好 Python”“反复关注相机画质”“近期寻找服务器部署方案”。不把询问当作爱好，
不把一次吐槽当作性格，不把他人的评价当作本人事实；职业／职责只有本人明确表述或有
明确署名的可信任务上下文时才形成待核实候选。禁止敏感属性、心理诊断和人格价值评判。

本人直接自述可以单条形成低支持事实；行为观察至少来自两个独立窗口，措辞为“近期多次
讨论”，而非永久偏好。模型候选必须引用原作者的消息；转发、引用、回复对象、第三方陈述
分开标注，无法确定主体就不写入画像。模型 confidence 不是本地校验的替代品。

明确期限的 need 随该期限失效；无期限临时 need 默认七天后 stale。偏好／观察特征默认
30 天无新支持标 stale，明确长期自述可配置更长复核期。到期只表示未确认仍有效，不能
推断需求已解决。矛盾证据保留 contested 或显式更正关系，不直接 last-write-wins。

人物摘要从已验证事实组成确定性模板，按群侧重点排序，但不丢弃不符合侧重点的重要需求。
先不额外调用模型润色每个人；后续如开启润色，只能在事实变化时有界合并，并计入同一预算。
用户能查看原文、纠正、隐藏、固定或删除派生档案；删除与撤销要有 suppression 记录，
防止下一次回放又生成，不能让模型清除用户纠正。

### 复用分析而不增加独立调用

版本化分析输出扩展 participant_claim_candidates 与 focus_candidates，复用话题的必要文本。
只有当前热池／固定人物和有界晋升候选才附带已有精简事实；初值每片最多八人、每人三条
相关事实、候选事实总计十二条，避免把全池档案塞回 prompt。没有新候选或变化就不更新。
未入模型的发言不能凭本地频率自动生成人物偏好，低支持可以只显示活动信息。
热池外的新人物单次明确求助仍可产生临时需求候选／重要信息卡；这不自动晋升长期画像，
也不因档案名额不足而隐藏行动信息。

人物事实、focus 候选、原阅读结果与该工作的来源／manifest 在同一事务校验发布；
摘要可确定性按需重建。热池排名统计有自己的游标与版本，不推进模型 covered_seq。
发布后定期合并是本地计算，不调用外部工具，也不写入个人 memory 或 matter。

## 调度与预算策略

不另建绕过现有 quota 的客户端。模型完整输入包括 codec 解释、schema、旧话题、人物事实、
focus 和本批文本；总体仍以当前 8192 输入、2048 普通输出限额为基线，保留恢复余量。
动态按 token 容量选择连续范围，不单纯按条数硬塞。现有单范围、服务、会话、共享后台
预算及公平让出、重试记账全部复用，具体当前上限见 API 合同，本文不提高生产限额。

人物／侧重点增加的输出也计入预算；候选过多时限制本次附带人物集合，不截断已有话题与
重要信息后假装成功。画像更新优先级低于重要信息和基本话题，预算不足可只积累本地索引。
热点关注、近期高活跃用户和模型重试均不能让其他群长期饿死。

第一轮远程试验拟上限十二次实际请求、累计 100000 输入加输出 tokens，失败、恢复与回读
都计入；按 provider 实际 usage 结算，缺 usage 保守记账。上限会提前中止矩阵，不承诺
十二次都能完成。未知模型单价时报告费用未知，不伪造 0；配置金额硬限额时必须有价格表。
这些只是待实施的试验预算，不是已经设定的配置或本轮远程调用承诺。

## 固定快照评测与迭代

### 样本与人工判定

从三群选择约 24 个窗口，覆盖高峰、安静时段、多个话题交织、低频公告、@／回复、
期限更正、噪声、同名昵称／引用归属和附件未知。按完整话题链分组，初始开发集 16 窗口、
保留集 8 窗口；跨边界链只进一组，避免相同事件泄漏。画像与群 focus 状态按时间顺序
重建，只能使用待评窗口之前已观察的消息；随机打乱窗口不能初始化长期画像。

用户标注主要话题、值得看原文、重要事件及更正、正确归属的人物候选。先抽十二个窗口
作小规模人工标注，未完成的保留集不拿模型自评当 gold。双人复核仅在存在争议的关键
样例时进行；模型评价可以辅助，但最终重要信息与画像归属由人工核对。

附加少量独立合成边界样例验证长文本、撤销、预算和时间问题，不伪装成真实聊天统计。
当前一天数据无法验证七天衰减和 14 天冷却，采用假时钟验证工程正确性，并继续列为
未来真实观察项目，不能宣称长期效果已通过。

### 对照与报告

当前 v2 链路作为工程兼容基线。新 schema 的语义对照三组使用相同模型、允许输入范围、
历史状态、输出字段和输出预算：A 完整文本普通结构，B 可还原紧凑编码，C 选择性输入。
先选四个已标注窗口覆盖三群，最多 12 次调用；剩余窗口按预算和已发现问题分轮，不一次
跑完整数据或全量 benchmark。固定种子、模型参数与 prompt/codec/selector/score 版本，
保留 provider 非确定性说明，不通过挑最好一次输出当结果。

| 指标 | 计算与注意事项 |
| --- | --- |
| 主要话题覆盖 | 人工主题召回与 Top5 有用比例；拆分／误合并单列 |
| 重要信息质量 | 按独立事件及关键更正计算召回、误报；不用多个证据重复计命中 |
| 来源正确性 | 结论被精确原文支持比例、跨人误归属数、无依据期限数 |
| 人物画像质量 | 被接受候选精度、敏感／不当推断、旧需求误复活、人工改写量 |
| 活跃池行为 | 换入换出次数、刷屏敏感度、新人等待、固定人物规则和容量 |
| 实际成本 | 每千条原始消息的输入／输出 tokens、请求、重试及画像增量开销 |
| 覆盖与延迟 | 模型实际读取比例、保护消息延期、选择性遗漏、最老积压与群间公平性 |

分母包含所有原始消息、失败请求和非输入消息，不只报告被选片段。重要事件本来不存在时
召回为 N/A，不记 100%；样本太少时提供命中／总数而非宣称可靠统计显著性。

拟定首轮发布门槛：确定性权限、身份与来源校验用例无越权、无跨人证据；人工发现的
关键行动／更正不能比 A 少；没有敏感画像和未经证据的确定结论。B 以不损失有效信息为
前提测量 token 收益；C 希望较 A 降低至少 30% 总 tokens，这是试验目标，不是预期事实。
C 未过质量门槛则不进入默认生产，B 没有实际收益则保留普通结构。画像候选精度初始目标
至少 90%，必须展示样本量；达到不了就先展示待核实信息，不自动写成稳定画像。
人工 gold 中约定必检的关键行动／更正必须全部命中；A 自己漏检时，B/C 同漏不算通过。
普通重要事件另报告召回与完整漏检清单。四窗口首轮至多证明可以进入下一轮评测，
生产启用还需锁定 holdout 和单群受控观察，不以小样本零漏检承诺真实世界零遗漏。

固定 holdout 不用于调阈值；每轮 badcase 先分类为捕获缺口、选择遗漏、语义错误、归属错误、
证据错误、排序或预算延期，只改相关组件。报告被取消／未跑样例，不把超预算矩阵当全部通过。
现有 `scripts/eval_message_reading.py` 仅提供合成回放与五条消息的远程探针，其 passed
主要表示工程与预算通过，不作为本批真实语义验收结果。另建显式快照回放入口，默认仍不外发。

## 存储接口和上线门槛

新增逻辑记录：SelectionManifest、ConversationFocusRevision、ParticipantActivity、
ParticipantProfile、ParticipantClaim、ParticipantSuppression，以及隔离回放的 snapshot/run/
labels/usage manifest。支持加法迁移，不重写原消息或已确认事项；派生对象都绑定会话、
来源代次、算法与语义版本。用户纠正和隐藏记录独立于模型输出。

拟新增 `/messages/reading/participants` 及人物详情／来源、群 focus 查看与 manual/auto
控制；用户纠正、固定与隐藏采用 CONTROL 身份和 expected_revision，Agent 仅新增只读工具。
不复用现有 `/messages/reading/profile` 改变其行为。接口仅为规划，实施时更新 API 合同、
受限前端代理和 Java 精确路由白名单；当前不可调用。

只在质量和兼容性验收后按单群 shadow → 有界正式分析推进。shadow 仍外发真实文本且
计费、需明确范围，不是假运行。上线时展示总预算、覆盖模式、模型、关注模式和人物保留规则；
保持采集在线，语义／画像失败不影响消息入库。关闭新算法恢复旧读取路线，不删除原文，
不让两条管线同时推进同一 generation。停用记录后所有派生读取重验许可，旧许可不复活；
停用分析停止新外发并保留可解释旧结果，provider 变更沿用已有再次确认逻辑。

## 持续人物档案与全量应用分析（2026-10-05）

人物档案不是单一“喜好标签”。在原文证据允许时记录交流方式、常谈主题、经验与角色
自述、情境变化、需求、偏好等不同维度；相同类别内不同 facet 可并存，不将不同主题
误认作矛盾。本人自述不等于核实事实，短期观察不等于稳定人格；敏感属性、心理诊断和
价值判断不生成。行为观察要有多条本人来源，跨时段支持不足时只作待确认信息。

档案使用平台/账户/会话/真实 sender 身份定位，昵称仅用于本地显示。模型使用快照化名，
发布前在本地还原来源，避免新快照排序变化造成串人。机器维护 Markdown/JSON、来源
时间范围和修订记录；人工 notes 独立且不由模型覆盖。滚动有效观察与有限历史分开，
过期、争议、归档状态明确，撤销代次不能重新发布旧证据。此独立历史档案入口不代表
已部署到 Windows 的服务开始持续更新；生产开关仍独立、默认关闭。

本次实测另发现：模型提供了本人原文支持的概括，但不满足严格“完整直接自述”或
跨时段观察条件时，完全丢弃会使有用档案变成空白。独立档案可显式启用待核实机器
摘记：只保留已经通过准确作者、时间、逐条原文、归属与敏感内容检查的提议；原拟定
类别/依据和未通过原因同时展示，不修改依据或伪装成已接受 claim。引用、作者、原文
或敏感内容校验失败的候选仍拒绝。摘记有独立过期/归档状态，不覆盖人工 notes，
不放宽生产的正式画像准入规则；补建摘记从已有模型结果本地回放，不增加远程调用。

用户本次另行授权三群完整已记录历史的应用分析，不沿用或重置旧十二次评测额度。
固定快照逐群按 seq 顺序分片，完整文本投影可还原，不以选择性抽样冒充全量。话题
延续由模型提供已知话题 key 及之前证据；上下文有界导致的分段明确记录。热度从实际
成员消息计数/作者多样性计算，重要信息和趣味亮点另列，附件内容保持未知。

独立显式 grant 绑定快照、模型、计划与有限调用/token 额度；请求、恢复和发布重验
原生 Windows 当前记录许可与 capture_epoch。历史应用属于用户按需任务，可显式使用
interactive 工作池，不更改自动后台限额；它与 Windows 生产账本不跨进程共享，不能
据此声称全局费用控制已经统一。未知模型价格不显示零费用。

覆盖报告列出所有计划批次、成功读取、未处理和未归入话题的来源，失败与结构修复也
计账。保留旧评测产物，全量应用结果不作为独立 holdout 或人工语义质量验收。
