# Linux 后端真实使用质量迭代（2026-10-05）

## 目标与边界

本轮不是功能数量或全量 pytest 的验收，而是验证日常任务能否自主、高效、可信地完成。
流程为：真实目标 → 基线/失败证据 → 原因 → 局部 TODO → 最小系统性修复 → 同题复测 → 留出题复核。
禁止针对题目、站点、邮件发件人或固定工具步骤在核心提示词中硬编码。

- Linux，仅后端；真实邮件已授权读取，测试写入隔离工作区与数据库。
- 用户补充授权其他本地文档用于模型测试，但明确禁止 `.env` 外发；不在输出或 Git 中记录密钥。
- 不发送邮件、不购买、不删除真实资料，不修改正式关注/记忆；正式服务不自动重启。
- 完整原文、prompt、trace、数据库和费用账本放在 gitignored `data/quality_runs/`。
- 可提交合成题目、匿名指标、失败原因和修复；不得提交密钥和真实邮件原文。
- 分支 `quality/linux-realworld-20261005`；起点 `2428baa`。
- 起点存在用户未提交的跨平台/消息阅读等改动：保持原样；每个完整迭代只提交本任务切片。

## 预算

用户给定 DeepSeek Flash 每百万 token：普通输入 USD 0.80，输出 USD 3.20，缓存读取 USD 0.016。
用户随后明确预算与定价同单位：**USD 50.00 总执行上限**，不进行人民币换算。
此前按更低 USD 5 上限执行的账本不清零，既有调用和费用继续累计。
另设累计 2000 次模型调用的防失控边界；它不替代 USD 50 金额上限。
Brave 搜索不超过 3000 次；采用跨运行持久账本，每次发出调用之前原子预留预算，失败/超时也计账。
未知缓存命中按普通输入计费；未知 usage 保留保守预留，不能按零计费。
测试不可绕过账本直接调用提供商；子开发 Agent 仅在根 Agent 的专项测试任务中使用同一账本。

## 评测方法

- 复用现有 fixture、数据集和协议回归；真实挑战只描述目标，不指定工具或解题步骤。
- 固定模型与配置，分别记录初始化与任务时间，不把 scripted 模式作为模型质量证据。
- 记录总耗时、首个有效反馈、LLM 调用/阶段、输入/输出/缓存 token、费用上界、工具失败与恢复、
  文件最终状态/执行退出码、覆盖率与证据支持；缺失指标标 unknown，不虚构为零。
- 外部网页动态变化采用带抓取时间的证据快照；现场搜索成功不等于回答事实得到支持。
- 改进题与留出题分开；不能仅以答案含关键词或另一个 LLM 的分数证明真实完成。
- 后台独立验证信息保留、用户纠错/撤回、作用域与前后台资源竞争。

### R6：压缩信息保留与真实困难边界

长用户消息尾部包含纠错/限制时，原 500 字符前缀摘要会丢掉它；汇总仅保留后缀又会丢开头的持久要求。
两例新回归修复前失败，改为首尾结构摘录，明确省略字符数；较长预算偏重最新尾部。
原文保持在会话与序列原始表，摘要只是有损视图，不声称理解中段所有重要信息。
追加 Unicode/0–8 token 小预算测试，修复了显式 0 被默认值替代、空窗口仍算分隔符等边界；
针对性 25 项通过。独立 review 进一步发现：多轮情况下最新一对原文可能自身超过上限，
这是仍需处理的硬预算边界，不能以小预算测试通过声称解决。

后台耗时基线：人工摘要器阻塞 150ms 时，前台 `record_context_exchange` 耗时 208ms，
确认硬阈值仍调用同步摘要器。后续应保留可语义重建的原始水位，给前台有损应急视图、
后台固定区间整理；不能把应急视图标为已完成语义覆盖而使 worker 跳过原文。

### R9：同题复测不是“工具加入就完成”

真实邮件复测 95.354s、12 次模型调用；分页不再复制错、字段投影确实读取了三页，
但发件人数量必要检查仅正确 3/30 组（6/60 封）。原因转移到**累计证据窗口**：
早期页面被固定 16,000 字符观测上限淘汰，模型为了拿回旧页又丢新页，不能稳定做全量统计。
合成同分布复测同样失败（135.489s；2/30 组正确），证明不是私有邮件特有问题。
开启 Planner 的合成题仍不自动 fork（66.809s；12/30 组、42/60 封必要数量覆盖）；
发现现有邮件专家配置默认关闭，先另做明确启用专家的隔离试验，不能归咎于专家执行器。
后续增加通用缓存确定性分组/计数，不靠模型在反复消失的页面里做加法，也不为邮件在核心加分支。

网页原题复测 69.017s（原 110.887s）、14 次模型调用；这轮真正使用一次 Brave 搜索，
仍有冗余顺序回读和很长回答，不能称为普遍 38% 提速。
现场最新版本任务 58.354s、13 次模型调用、2 次 Brave：读取官方发布记录，核对版本、
发布时间和变更，正确区分旧版本搜索片段；恢复了一次 JSON API 打开失败，引用关键来源可追溯。
快照中的版本不是今后的固定正确答案；完整证据留在私有 report。

原生隐式结束修复加上 compact token 长度/ASCII review 后，相关 46 项通过。
老式单客户端增加显式 `supports_json_mode` / `supports_function_calling` 配置透传，
默认仍为 false，不按模型名猜能力；两例透传回归先失败，修复后 LLM/推理控制 15 项通过。
仅已实测通过的 JSON mode 在本地忽略配置中开启，native 未开启；正式运行进程未重启，
